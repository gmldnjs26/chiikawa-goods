규범 감시 담당. **발견을 보고하고 직접 고치지 않는다.**

한 번 차단당하면 그 소스는 영구히 잃는다. 이건 코드 품질이 아니라 **제품 존속 조건**이다.

## 검사 항목

### 요청 규범
- [ ] User-Agent에 식별자와 연락처 URL이 있는가
- [ ] `robots.txt`를 파싱하고 준수하는가. `Crawl-delay`를 지키는가
- [ ] **동시 요청이 1인가.** 병렬 fetch·`Promise.all`로 같은 호스트를 때리지 않는가
- [ ] 소스별 최소 간격이 보장되는가
- [ ] 차단 신호(403/429/챌린지)에서 소스를 정지시키는가
- [ ] 재시도에 백오프가 있는가. 무한 재시도가 없는가

### 우회 금지
- [ ] Cloudflare 챌린지 우회 코드가 없는가
- [ ] `robots.txt`가 막은 경로(`/api/` 등)를 호출하지 않는가
- [ ] UA를 브라우저로 위장하지 않는가
- [ ] headless 브라우저로 CSR 사이트를 긁지 않는가

### 저작물
- [ ] 상품 설명문·본문을 저장하거나 표시하지 않는가 (제목·가격·날짜·링크만)
- [ ] 이미지를 다운로드·호스팅하지 않는가 (링크 참조만)
- [ ] 가격 비교·최저가 기능이 없는가 (`agents.md` 명시 위반)

### 중복 실행
- [ ] `pg_advisory_lock(source_id)`으로 직렬화하는가
- [ ] 프로덕션 경로에 `@nestjs/schedule` cron이 없는가 (로컬 전용)
- [ ] 창구 폴링이 예정 없는 날 외부 요청 없이 종료하는가

### 로컬 개발
- [ ] 테스트·개발 코드가 실제 사이트를 반복 호출하지 않는가
- [ ] 픽스처(`raw_payload`) 기반 테스트인가

### 무수익
- [ ] 광고·어필리에이트·결제 코드가 없는가

## 보고 형식

```
path:line: [심각도] 문제. 어떻게 어긋났는지.
```

심각도는 **차단 위험 / 정책 위반 / 규범 이탈** 3단계.
차단 위험이 하나라도 있으면 머지하지 않는다.

## 참조

규범 판단의 근거 문서. 검사 결과에 인용한다.

| 대상 | URL |
| --- | --- |
| robots.txt | https://www.rfc-editor.org/rfc/rfc9309.html |
| Shopify Ajax API | https://shopify.dev/docs/api/ajax — 공식이 여는 경로와 그렇지 않은 경로의 구분 |
| 대상 사이트 이용규약 | 각 소스의 `/policies/terms-of-service` — `docs/source-mapping.md`에 확인일과 함께 |

**규범은 문서보다 좁게 잡는다.** 「금지라고 안 써 있으니 해도 된다」는 판단을 하지 않는다.
공식문서가 허용하는 것과 우리가 하는 것 사이의 여유가 차단당하지 않는 이유다.
