## 0. 요약

- **문제**: 치이카와 굿즈 발표가 8개 이상 채널로 흩어져 있다. "지금 살 수 있는 것"을 한 곳에서 볼 수 없다.
- **해법**: 흩어진 발표를 모아 **하나의 타임라인**으로 보여주고, 열리는 순간 **알린다.**
- **차별점은 딱 두 개**: (1) 읽으러 가는 기사가 아니라 **타임라인 + 푸시**, (2) **최대 20일 전 예약 사전 감지.**
- **하지 않는 것**: 가격 비교, 이미지 게재, 커뮤니티, 구매 대행, 수익화.
- **첫 릴리스(v0) = 수집 + 공개 화면.** 알림은 v0.5로 미룬다 — 빈도를 실측으로 정하기 위해서다.
- **가장 큰 제약**: 재류자격 — **무수익이 기본값.** 광고·어필리에이트는 별건 검토 사항이다.

## 1. 제품 정의

### 1.1 문제

치이카와 굿즈 발표가 **공식 스토어 · くじ · 프라이즈 · 편의점 · 식완 · 콜라보 · 실점포**로 흩어져 있다.
각 채널이 자사 사이트와 X에 따로 발표하므로 **현황을 한 곳에서 볼 수 없다.**

구조적으로 놓치기 쉬운 것이 두 가지다.

1. **예약 개시** — 사전 공지 없이 열리고, 몇 시에 열리는지가 어디에도 안 적혀 있다.
2. **재입고** — 사전 예고가 **0일**이다. 그 순간을 못 보면 그대로 끝난다.

### 1.2 사용자

- 1차 사용자: **일본 거주 치이카와 팬**
- 서비스 언어: **일본어** (설계 문서만 한국어)
- 행동 목표: *"지금 살 수 있는 것"과 "곧 열리는 것"을 10초 안에 파악한다.*

### 1.3 차별점 — 두 개뿐이다

| | 기존 팬 블로그 4곳 | 이 서비스 |
| --- | --- | --- |
| 형식 | 블로그 기사 (읽으러 가야 함) | **타임라인 + 푸시** |
| 예약 사전 감지 | 없음 | **최대 20일 전 감지** |

> [!warning] 이 두 개가 흐려지면 무너진다
> 기능 추가 판별 질문: **"이거 블로그도 할 수 있나?"** → 예스면 하지 않는다.
> 콘텐츠 경쟁에 발을 들이면 매일 갱신하는 네이티브 운영자들에게 진다.

### 1.4 비목표 (Non-goals)

| 하지 않는 것 | 이유 |
| --- | --- |
| 가격 비교 · 최저가 추적 | 공식 스토어 정책 명시 위반 (§2.1) |
| 상품 이미지 · 설명문 게재 | 저작물. **공식 페이지로 링크만** |
| 커뮤니티 · 댓글 · 거래 중개 | 운영 부담이 커져 개인 운영이 무너진다 |
| 구매 대행 / 자동 결제 | 공식 정책이 금지 |
| 완전 자동 100% 커버리지 | 구조적으로 불가능 (§2.3) |
| SEO 기반 유입 경쟁 | 기존 블로그 4곳과 싸우지 않는다 (§9) |

### 1.5 성공 기준

| 단계 | 기준 | 확인 방법 |
| --- | --- | --- |
| v0 | 한 달 운용에 **빠진 발표가 없다** + **"이거 없었으면 놓쳤다"가 3회 이상** | 수집 이력 점검 + 본인 수기 기록 |
| v0.5 | 알림 빈도가 실측 기반으로 확정됨 | 한 달치 전이 이력 |
| v1 | 본인 외 실사용자 1명이 계속 씀 | 2주 연속 재방문 |
| v1.5 | 푸시 구독자 100명 | 구독 수 |

## 2. 제약

### 2.1 정책 — 제품 범위를 여기서 정한다

공식 스토어가 문서로 허용 범위를 밝히고 있다 (`chiikawamarket.jp/agents.md`).
**이 문서가 §1.4 비목표 전체의 근거다.**

| 허용 | 금지 |
| --- | --- |
| **상품명 · 가격을 안내 목적으로 참조** | 가격 비교 · 전매 목적 수집 |
| 공식 페이지로의 링크 | 이미지 · 설명문 전재 |

일부 소스는 접근 자체가 막혀 있거나 정책상 쓰지 않기로 한다. 우회 수단이 있어도 쓰지 않는다.
**출처를 밝힐 수 없는 취득 경로는 제품에 넣지 않는다** (§7.3).

### 2.2 운영 규범

- 우리가 누구인지 밝히고 연락처를 공개한 상태로 수집한다
- 각 사이트가 요구하는 접근 간격을 지킨다. 상대 서버에 부담을 주지 않는다
- 원문을 그대로 옮기지 않는다 — **제목 · 가격 · 날짜 · 링크만**
- **삭제 요청 창구를 공개 시점부터** 운영한다 → v0부터 필요하다 (§8)
- 차단 신호를 받으면 그 소스를 **즉시 중단**한다

> 이 규범은 예의가 아니라 **제품 존속 조건**이다. 한 번 차단당하면 그 소스는 영구히 잃는다.

### 2.3 재류자격

취업비자 기준 **무수익이면 문제 없다.**
어필리에이트·광고를 붙이는 순간 계속적 수익 활동이 되어 별도 허가가 필요하다.

→ **무수익을 기본값으로 확정.** 수익화는 별건으로 재검토.
→ 참고: [[일본 유흥 가이드 법적 제약]] 5장

### 2.4 커버리지의 한계

- 자동 수집으로 덮이는 건 **다수지만 전부는 아니다.** 실점포·팝업은 발표 기반이라 한계가 있다
- 발표가 몇 시간 만에 흘러가 버리는 채널이 있다 → **놓치면 복구 불가**
- 사이트가 "정상"이라고 응답하면서 실제로는 빈 내용을 주는 경우가 흔하다 → 신뢰할 수 없다

**100%를 약속하지 않는다.** 지금이 0%다.

## 3. 제품 규칙

### 3.1 사용자가 보는 단위 = 발표 단위

굿즈 하나하나가 아니라 **"발표" 하나**가 화면·알림의 단위다.
신작 20종이 한 번에 나왔다고 알림을 20개 보내면 스팸이다.

### 3.2 상태 — 3개만 보여준다

| 상태 | 사용자에게 보이는 것 |
| --- | --- |
| 예약 예정 | 🔜 + 며칠 남았는지 |
| 지금 구매 가능 | 🟢 |
| 매진 / 종료 | 🔴 (회색 처리) |

**재입고는 상태가 아니라 "사건"이다.** 매진된 것이 다시 살 수 있게 된 순간을 가리킨다.
그리고 이건 **반복된다** — 재입고 후 다시 매진, 또 재입고. 한 번만 알리면 안 된다.

### 3.3 유형별 예고 가능 시간이 다르다

알림 정책이 여기서 갈린다.

| 유형 | 미리 알 수 있는 시간 | 알림 방식 |
| --- | --- | --- |
| **예약** | 보통 3일, 최대 20일 | 발견 즉시 + 전날 + 개시 직전 |
| **발매** | 3일 전 (단 **내용은 비어 있다**) | "그날 뭔가 나온다"만 먼저, 내용 확정 후 다시 |
| **재입고** | **0일** | 감지 즉시 1회. 매번 |

### 3.4 시각은 추정치다

몇 시에 열리는지가 사이트 어디에도 안 적혀 있다.
실측해 보면 **발매는 11시, 예약은 18시**가 많지만 예외가 있다.

→ **날짜는 확정으로, 시각은 "추정"으로 표기한다.** 확정인 척하지 않는다.

## 4. 커버리지 로드맵

한 번에 다 덮지 않는다. 차별점이 가장 선명한 곳부터 간다.

| 단계 | 대상 | 이유 |
| --- | --- | --- |
| **1단계 (v0)** | 공식 스토어 2곳 | **예약 사전 감지가 여기에만 있다.** 차별점의 근원 |
| **2단계 (v1)** | 보도자료 · 편의점 3사 · 식완 · 가챠 · 의류 콜라보 · 주요 팬 사이트 | 발표량이 많은 채널 |
| **3단계 (v1.5)** | 게임센터 프라이즈 · 프리미엄반다이 · 베이커리 등 | 갱신 빈도가 낮음 |
| **보류** | 一番くじ · 실점포 · 수동 입력 | 정책 제약 또는 비용 |

취득 경로·주기 등 구체는 [[data-collection-design]].

> [!note] v0가 40%만 덮어도 된다
> 지금은 0%다. 한 곳에 모여 있으면 그 자체로 낫다.
> **소스 12개를 처음부터 만들지 않는다.**

## 5. 알림 정책

> [!note] **v0에는 알림이 없다. 화면은 있다.**
> 화면을 먼저 공개하고, 알림은 한 달치 전이 이력을 본 뒤 붙인다.
> 실제로 언제 몇 번 나가는지를 모르는 채 정한 빈도는 사용자를 잃는다.

| 언제 | 내용 |
| --- | --- |
| 예약 정보 신규 감지 | 최대 20일 전 예고 |
| 개시 전날 | 리마인더 |
| **실제로 열린 순간** | **가장 중요** |
| 재입고 | 사전 예고 불가. 매 회차 알림 |

원칙

- **발표 단위로 묶어서 1건** (§3.1)
- 카테고리별 구독 — くじ / 프라이즈 / 편의점 / 식완 / 콜라보 / 실점포
- v0.5는 본인 전용 채널 → v1에 웹 푸시
- LINE Notify는 2025-03 종료 → 쓰지 않음

## 6. 화면

### 6.1 홈 — 2섹션이면 끝난다

```
🟢 今すぐ買えるもの      ← 최상단. 행동 가능한 것만
🔜 もうすぐ開きます       ← 8일 전 ~ 당일
──────────────────────
📅 発売カレンダー
🗄 過去 / 完売
```

### 6.2 카드 구성

상품명 / 가격 / 판매처 / **상태** / 남은 시간 / 공식 링크

이미지는 **원본 링크 참조만.** 우리가 갖고 있지 않는다 (§1.4).

### 6.3 카피 톤

일본어 서비스다. 팬덤에는 고유한 말투가 있으므로 사무적 표기로 도배하지 않는다.
**공개 전 톤 검수 1회**를 릴리스 조건에 넣는다 — v0 릴리스 조건이다. 현재 문안은 전부 임시안이다.

### 6.4 출처 표기

각 항목에 출처 링크를 명시한다.

이유 2개 — (1) 집계 서비스의 신뢰성 근거, (2) **기존 팬 블로그 4곳이 하지 않는 것**
(운영자 신원 비공개, `/about` 404).

밝힐 수 없는 경로로 얻은 정보는 애초에 싣지 않는다.

## 7. 운영 원칙

| 항목 | 원칙 |
| --- | --- |
| 조용한 실패 감지 | 소스가 죽어도 화면은 멀쩡해 보인다. **이게 가장 위험하다.** 소스별로 마지막 성공 시각을 감시 |
| 소스 단위 중단 | 문제가 생긴 소스만 끄고 나머지는 계속 돈다 |
| 잘못된 정보 정정 | 자동 병합이 틀렸을 때 **손으로 고칠 수단**을 처음부터 만든다 |
| 삭제 요청 대응 | 공개 시점부터 창구 운영 |
| 지속 가능성 | 수동 작업을 늘리지 않는다. 손이 많이 가면 방치된다 |

## 8. 마일스톤

| | 기간 | 범위 | 완료 조건 |
| --- | --- | --- | --- |
| **v0** | 1~2주 | 공식 스토어 2곳 수집 + **홈 2섹션 + 상태 표시 + 출처 표기. 웹 공개** | 한 달 운용, 누락 없음 + "놓칠 뻔했다" 3회 |
| **v0.5** | 1~2주 | 발매 캘린더 + 본인용 알림(Discord) | 알림 빈도 확정 |
| **v1** | 1~2개월 | 2단계 소스 전부 + 웹 푸시 + 카테고리 필터 | 실사용자 1명 정착 |
| **v1.5** | — | 3단계 소스 + 실점포 + 반자동 입력 | 푸시 구독자 100명 |

### 8.1 v0 착수 조건

v0을 공개하므로 아래가 착수 전 확정 항목이다.

| 항목 | 왜 v0인가 |
| --- | --- |
| 서비스명 · 도메인 | 공개 URL이 필요하다 |
| 이용약관 · 면책 문구 | 집계 정보의 정확성 면책. 공개 즉시 필요 |
| **삭제 요청 창구** | §2.2가 "공개 시점부터"를 요구한다 |
| 일본어 카피 톤 검수 1회 | §6.3 릴리스 조건 |
| 출처 표기 UI | §6.4. 신뢰성 근거이자 차별점 |

> [!important] v0에 알림이 없다
> 차별점 2개 중 **푸시가 첫 릴리스에 없다.** 화면(타임라인)은 v0에 들어가므로 절반은 성립한다.
> 알림을 v0.5에 두는 이유는 개발량이 아니라 **빈도를 실측 없이 정할 수 없어서**다.
> 한 달치 전이 이력을 본 뒤 붙인다.

## 9. 리스크

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 기존 블로그 4곳과 경쟁 | 유입 없음 | **콘텐츠·SEO로 안 싸운다.** 알림과 상태 표시로만 |
| 소스 사이트 사양 변경 | 해당 소스 사망 | 원문 보존으로 재처리 + 무음 감지 |
| 조용한 실패 | 신뢰 상실 | 소스 헬스 감시 (§7) |
| 정보 오병합 | 정보 왜곡 | 수동 정정 창구 (§7) |
| 크롤링 차단 · 항의 | 소스 영구 상실 | 운영 규범 준수 + 즉시 중단 + 연락처 공개 (§2.2) |
| **인프라 무료 크레딧 소진** | 고정비가 자기 부담으로 남음 | 만료 30일 전 재판단. 이전 경로 확보 ([[tech-stack]] §2.6) |
| 수익화 유혹 | **재류자격** | 무수익 기본값 고정 (§2.3) |
| 개인 운영 지속성 | 방치 | 자동화 비율을 높게 유지 |
